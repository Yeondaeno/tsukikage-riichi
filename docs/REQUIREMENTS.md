# 월영마작 v3 개선·구현 프롬프트

## 0. 역할과 작업 기준

너는 웹게임 개발자, 리치마작 UI·UX 설계자, 게임 아트 디렉터, 캐릭터 디자이너, QA 담당자의 역할을 함께 수행한다. 기존 `월영마작(TSUKIKAGE RIICHI) v2`를 실제로 플레이할 수 있는 캐릭터 중심 웹게임으로 개선하라. 기획 설명이나 스크린샷용 목업에서 끝내지 말고, 게임 상태·조작·캐릭터·연출·안내가 연결된 실행 가능한 결과물을 제작하라.

작업 기준은 제공된 `tsukikage-riichi-v2.html`과 `tsukikage-riichi-v2-source.zip`이다. 소스 ZIP을 우선 확인하고 실제 파일 위치를 찾아 사용하라. 소스가 보이지 않으면 연결된 작업공간과 제공 파일을 먼저 확인하되, 찾지 못한 파일을 읽었다고 주장하지 않는다. 기존 파일은 보존하고 별도 버전이나 브랜치에서 작업한다. 코드에 접근할 수 없는 상태에서 임의로 새 게임을 만들어 기존 게임 개선을 완료했다고 보고하지 않는다.

핵심 목표는 ‘작혼: 리치 마작·마작일번가를 참고한 직관적인 조작과 정보 전달’, ‘분명하게 읽히는 패와 리치 상태’, ‘만관 이상에서 특별하게 느껴지는 캐릭터 화료 연출’, ‘개입 정도를 선택할 수 있는 초보자 안내’다. 참고 게임의 캐릭터·일러스트·음성·UI 자산을 그대로 복제하지 말고 독자적으로 제작한다.

이미 합의된 요구사항은 다시 질문하지 않는다. 미정인 세부 디자인과 구현 방법은 아래 기본안을 사용하고 변경 가능한 설정·데이터로 분리한다. 단, 실제로 필요한 권한·유료 서비스·배포 대상 등 승인 사항은 임의로 결정하지 않는다.

## 1. 구현 범위와 설계 전용 범위

### 이번 버전에 실제 구현

플레이어 1명과 CPU 3명의 4인 리치마작을 유지하고, 웹주소로 접속할 수 있는 배포 구조로 전환한다. PC와 휴대폰 가로 화면을 모두 지원한다. 패·버림패 가독성, 재클릭·드래그 조작, 리치 표시와 공탁봉 연출, 좌측 상단 왕패·도라 안내, 도라 강조, 점수·순위 변동, 만관 이상 등급별 화료 연출을 모두 구현한다.

고정 캐릭터 4명의 디자인·표정·컷인·상황별 대사와 필요한 게임 소재를 직접 제작하여 게임에 연결한다. CPU 3명은 공격형·수비형·균형형으로 실제 대국 판단을 차별화한다. 초보자 가이드는 개입 수준을 조절할 수 있게 만들고, 패 보조 표기·연출·음향 설정을 각각 분리한다.

이 항목들은 모두 필수다. 개발 순서를 나누더라도 하위 순위로 취급하여 제외하거나 목업으로 대체하지 않는다.

### 이번에는 설계만 수행

대전 모드 분리, 리플레이, 패보, 전적 통계를 위한 모듈 경계·데이터 형식·인터페이스·화면 흐름·검수 계획을 설계한다. ‘전보’라는 표현은 이 문서에서 ‘패보’, 즉 대국의 진행을 기록하는 데이터라는 의미로 정리한다.

현재 작동하는 대전은 CPU 대전이다. 일반전·랭크전 등 향후 모드는 확장 예시로 구분하되 이번에 온라인 매칭이나 랭크 서비스를 실제 구현하지 않는다. 리플레이 플레이어·패보 관리 화면·통계 대시보드도 이번 필수 구현에 포함하지 않는다. 다만 추후 재구축을 피할 수 있도록 현재 코드의 규칙·입력·이벤트·화면 경계는 정리한다.

계정·결제·가챠·재화·캐릭터 수집·호감도·클라우드 동기화는 확정된 요구사항이 아니므로 추가하지 않는다. 웹주소 접속을 온라인 멀티플레이 구현 요구로 해석하지 않는다. 준비되지 않은 기능을 작동하는 버튼처럼 노출하지 않는다.

## 2. 기존 기능 보존과 변경 원칙

시작 전에 기존 규칙 엔진, 점수 계산, CPU 판단, 입력 처리, 저장 형식, 테스트를 확인하고 현재 상태를 기록한다. 과거 테스트 통과 기록을 이번 변경의 검증 결과로 재사용하지 않는다.

1국 연습·동풍전·반장전, 치·퐁·깡·리치·론·쯔모, 도라 계열, 본장·공탁금·유국·친 이동 등 기존에 실제 구현된 기능은 보존한다. 규칙 오류를 발견하면 재현 테스트를 만든 뒤 고치고 변경 이유를 기록한다. 화면 개선을 이유로 계산 엔진을 무검증 상태에서 전면 교체하지 않는다.

기존과 새 입력 요구가 충돌하면 새 입력 요구를 우선한다. 기존의 빠른 더블클릭 제한, 자동 선택, 버리기 단축 경로, 자동 쯔모기리 기본값 등이 안전한 두 단계 조작을 무력화하지 않는지 확인한다. 자동 쯔모기리 같은 기존 자동 기능을 유지할 경우 수동 조작과 명확히 분리하고 기본값은 꺼짐으로 두며, 사용자 동의 없이 활성화하거나 기존 설정을 몰래 승계하지 않는다.

기존 하우스 룰과 미지원 규칙은 문서화한다. 공식 규칙 전체와 동일하거나 모든 예외가 검증되었다고 주장하지 않는다. 요청하지 않은 룰 변경을 시각적 연출에 섞지 않는다.

## 3. 화면 방향: 화사한 월영마작

기존의 녹색 마작탁·청옥·달빛 정체성을 남기되, 밝은 아이보리 패·맑은 민트·은은한 금빛·부드러운 애니메이션풍 배경으로 더 화사하게 바꾼다. 단순히 다크 대시보드에 캐릭터 그림을 추가하는 방식은 피한다.

화면의 시각적 우선순위는 ‘내 손패와 버림패 → 현재 차례·점수·리치 → 도라·왕패 → 캐릭터 반응 → 배경 장식’으로 한다. 캐릭터 일러스트나 설명 패널이 패를 작게 만들거나 가리지 않도록 설계한다. 평상시에는 초상화 중심으로, 리치·화료 같은 중요 순간에는 컷인으로 존재감을 키운다.

PC에서는 넓은 대국판을 중심에 배치하고 가이드 패널을 접을 수 있게 한다. 휴대폰에서는 PC 화면을 통째로 축소하지 말고 가로 화면에 맞게 재배치한다. 불필요한 상단 바와 고정 사이드바를 줄이고, 설명·기록·상세 순위는 필요할 때 여는 패널로 전환한다.

모바일 세로 화면에는 회전 안내와 설정 접근을 제공하되, 회전 잠금·전체화면 기능을 사용할 수 없어도 게임이 막히지 않게 한다. 화면 회전, 주소창 높이 변화, 노치와 안전 영역을 고려한다. 가로 대국 화면에서는 손패·핵심 행동·각 플레이어 버림패를 보기 위해 페이지를 스크롤하지 않아도 되도록 한다.

대표 검수 크기는 PC 1920×1080·1366×768, 모바일 가로 844×390·740×360 CSS 픽셀로 잡는다. 이는 설계·검수 기본안이며 사용자의 실제 기기 정보로 주장하지 않는다.

## 4. 패 디자인·버림패 가독성

마작패는 축소해도 만·통·삭과 자패를 구별할 수 있도록 새로 설계한다. 문양 자체의 선명도, 획 굵기, 간격, 여백, 대비를 우선하고, 입체 옆면·반사광은 문양을 가리지 않는 범위에서 적용한다. 운영체제별로 모양이 달라지는 마작 이모지나 폰트 문자만으로 패를 표현하지 않는다. SVG 또는 검수한 고해상도 자산으로 34종과 적패 변형을 일관되게 제작한다.

정통 문양을 기본으로 하고, 숫자·패 종류·자패 이름을 도와주는 ‘초보자용 패 표기’를 ON/OFF할 수 있게 한다. 내 손패뿐 아니라 버림패·공개된 몸통·확대 보기에도 설정을 일관되게 적용한다. 적도라와 일반 5패를 색상 외의 작은 표식으로도 구분한다.

네 사람의 버림패는 줄·순서·방향을 정확히 유지하고, 마지막 버림패·리치 선언패·선택한 패와 같은 종류의 공개패를 서로 다른 시각 언어로 표시한다. 리치 선언패를 위한 가로 공간을 실제 레이아웃에 반영하여 회전한 패가 옆 패와 겹치지 않게 한다.

PC에서는 올려보기, 모바일에서는 선택 또는 별도의 확대 조작으로 패 이름과 공개패를 자세히 볼 수 있게 한다. 버림패 영역을 확대해 읽는 기능도 제공한다. 확대·설명·닫기 조작은 절대로 버리기 입력으로 전달되지 않아야 한다. 공개된 같은 종류의 패 강조는 실제 패 종류와 적패 상태를 명확히 구분하며, 비공개 손패나 패산 정보는 표시하지 않는다.

## 5. 패 조작: 원클릭 버리기 절대 금지

수동 버리기는 아래 두 경로로 구현한다.

**선택 후 재클릭·재터치:** 처음 누른 패는 선택만 된다. 선택한 바로 그 패를 다시 누르면 버린다. 다른 패를 누르면 선택만 바뀐다. 두 번째 입력은 빠른 더블클릭일 필요가 없으며, 잠시 생각한 뒤 다시 눌러도 작동한다. 같은 종류의 다른 실물 패를 누른 경우에는 ‘같은 패 재선택’으로 오인하지 않는다. 빨간 5와 일반 5도 고유 식별자로 구분한다.

**드래그 버리기:** 내 손패를 잡아 명확한 버림 영역으로 끌어 놓으면 버린다. 패 들림·가벼운 기울기·드롭 영역 강조로 결과를 예고한다. 임계 이동거리 미만, 영역 밖 놓기, 포인터 취소, 화면 회전, 모달 진입, 차례 변경에는 버리지 않고 원위치로 돌아간다. 작은 손떨림은 드래그 확정이 되지 않아야 한다.

원클릭 즉시 버리기는 기본 조작·설정 옵션·빠른 모드·모바일 간편 모드 어디에도 추가하지 않는다. 추천패나 쯔모패를 자동 선택해 첫 입력에 버려지게 하지 않는다. 기존 Enter·버리기 버튼·키보드 접근성을 유지한다면 ‘사용자가 명시적으로 선택한 뒤 별도 확정’이라는 동일한 계약을 지키고 미선택 상태에서 버리게 하지 않는다.

드래그가 끝난 뒤 발생하는 클릭, 터치 뒤 합성 클릭, 이벤트 중복 등록으로 두 장이 버려지지 않도록 처리한다. 입력은 현재 차례·행동 가능 여부·화료 연출·가이드 모달 상태를 확인한 후 한 번만 확정한다. 렌더링이나 자동 정렬로 선택한 패의 식별자가 바뀌지 않게 한다. 이미 확정한 버림을 연출 취소로 되돌리지 않는다.

치·퐁·깡·리치·화료 버튼은 가능한 상황에만 활성화하고, 조합을 고르는 경우 패를 크게 보여준다. 리치를 누르는 행위는 선언패 선택 단계로 들어가는 것이며 임의의 패를 즉시 버리지 않는다.

## 6. 리치 선언패·공탁봉·지속 표시

리치 가능 상태, 선언패 선택 중, 리치 성립 상태를 구분한다. 선언패를 확정하면 캐릭터 반응·짧은 선언음·리치 표시·선언패 회전을 보여주되, 리치의 실제 성립 여부와 점수 이동은 엔진의 판정을 따른다.

선언패는 소유자의 버림패 방향을 기준으로 90도 눕힌다. 색칠이나 밑줄만 추가하고 ‘가로 리치패 구현’이라고 하지 않는다. 회전으로 달라진 폭을 반영하고 네 좌석에서 정확히 배치한다. 선언패가 다른 사람에게 가져가진 경우에도 선언 위치·순서를 알 수 있는 표시를 유지하며, 대체 표시 방식은 적용 룰과 함께 명시한다.

리치가 성립하는 시점에 플레이어 쪽에서 중앙 공탁 영역으로 1,000점 공탁봉이 이동하는 모습을 보여준다. 점수 차감, 공탁봉 개수·금액, 리치 배지가 같은 실제 이벤트에 맞춰 갱신되어야 한다. 선언패에 론이 발생해 리치가 성립하지 않는 경우 등 예외에서도 잘못 차감하거나 공탁봉을 남기지 않는다.

선언 컷인이 사라진 뒤에도 ‘가로 선언패 + 플레이어 리치 배지 + 중앙 공탁 표시’로 상태가 명확히 남아야 한다. 여러 명이 리치했을 때 누구의 선언인지 구별되고, 리치 후 장식이 손패·버림패·행동 버튼을 가리지 않게 한다.

## 7. 좌측 상단 왕패와 도라 강조

PC와 모바일 가로 화면 모두 게임 영역 좌측 상단에 왕패·도라 표시 영역을 유지한다. 중앙 보드 안에만 넣거나, 모바일 축소 때문에 읽을 수 없게 만들지 않는다. 상대 초상화·버림패와 겹치지 않는 자리를 확보한다.

왕패 영역에는 공개된 도라 표시패와 아직 공개되지 않은 뒷면을 구분한다. 7개 2단 스택 표현을 유지하거나 더 읽기 쉬운 표현으로 개선하되, 깡·영상패 처리 후의 공개 상태는 엔진과 일치시킨다. 확인할 수 없는 패를 채워 넣어 실제 왕패인 것처럼 보여주지 않는다.

‘도라 표시패’와 ‘현재 도라’를 이름과 레이아웃으로 구분한다. 실제 도라 안내는 가이드와 별도로 켜고 끌 수 있게 한다. 새 깡도라는 깡이 실제 성립한 뒤에만 공개하는 연출로 연결한다.

실제 도라·적도라에는 문양을 가리지 않는 금빛 테두리·별 표식·부드러운 반짝임을 사용한다. 내 손패와 공개된 패에 일관되게 적용하며, 보너스가 겹칠 때의 표시 수치는 엔진 결과에 따른다. 패 보조 숫자와 도라 배지가 겹치지 않게 배치한다.

반짝임을 끄거나 모션을 줄여도 정적인 테두리·표식은 남겨둔다. 도라 표시패 자체를 실제 도라와 혼동하도록 강조하지 않는다. 우라도라 공개·강조는 공개 가능한 결과 상태와 해당 화료자에게만 적용한다. 여러 화료자가 있는 경우도 각자 올바르게 처리한다. 대국 중에는 숨겨진 왕패·우라도라·CPU 손패가 DOM, 접근성 이름, 툴팁, 이미지 경로, 네트워크 데이터에 불필요하게 노출되지 않도록 화면용 데이터를 분리한다.

## 8. 등급별 화료 연출

모든 화료는 규칙 엔진이 확정한 결과로 시작한다. 실제 계산이 만관·하네만·배만·삼배만·역만 중 어느 등급인지 확인하여 연출을 선택한다. 받은 점수 숫자만 비교해 등급을 결정하지 않는다. 친·자, 론·쯔모, 본장·공탁금이 다르더라도 화료 등급 표시는 정확해야 한다.

일반 화료에는 짧고 명확한 기본 연출을 사용한다. 만관 이상에는 ‘캐릭터 등장 → 화료패 강조 → 역을 순서대로 공개 → 판·부·등급·최종 점수 → 점수 이동·순위 변동’으로 이어지는 전용 연출을 구현한다.

만관은 캐릭터 컷인과 달빛 파동, 하네만은 더 넓은 빛의 흐름, 배만은 전용 구도와 강화된 캐릭터 모션, 삼배만은 배경 전환과 더 큰 공간감, 역만은 특별 컷인과 전용 상징 연출로 구분한다. 실제 지원하는 복합·더블 역만은 엔진 정보가 있을 때만 표시한다. 등급마다 제목과 색상만 바꾸는 재사용은 피하되 공통 타임라인과 자산 재사용 구조는 유지한다.

여기에 캐릭터별 상징을 결합한다. 플레이어의 초승달, 공격형의 햇살과 리본, 수비형의 물결과 수정, 균형형의 꽃잎과 바람을 사용하되 패·역·점수의 가독성이 우선이다. 저점 화료도 무성의하게 처리하지 않지만 고등급 연출과 분명한 차이를 둔다.

론·쯔모·더블 론 등 결과 유형을 정확히 전달한다. 여러 화료자가 있으면 각자의 손패·역·보너스·등급을 보여주고 정산을 한 번만 적용한다. 유국에 화료 연출을 재사용하지 않는다.

연출은 풍부하게·짧게·끄기로 설정하고, 전체 연출과 별개로 화면 흔들림·도라 반짝임을 조절한다. 화면상 건너뛰기 버튼을 PC·모바일 모두 제공한다. 건너뛰기·설정 변경·다른 화면 이동 시 타이머·입자·음향을 정리하고, 정산 중복·점수 누락·다음 국 중복 시작을 방지한다. 건너뛰기 입력이 뒤의 패 선택이나 다음 국 시작 버튼까지 전달되지 않아야 한다.

정산은 실제 상태에 한 번만 반영하고 카운트업은 표시 값에만 적용한다. 연출 완료 콜백이 유실되더라도 대국이 영원히 잠기지 않게 한다. 연출 미리보기는 격리된 샘플 상태를 사용하여 실제 손패·점수·패산·차례·저장·난수 상태를 변경하지 않는다.

## 9. 점수와 순위 변동

네 사람의 현재 점수·순위·차이를 확인할 수 있게 한다. 정산 전후 순위를 비교해 상승·하락·유지를 표시하고, 실제 순위 변화가 있을 때 카드나 순위 표시가 부드럽게 이동하게 한다.

카운트업 중간 숫자 때문에 순위가 여러 번 뒤집히지 않도록 최종 순위는 확정된 점수와 게임의 동점 규칙으로 계산한다. 리치 공탁, 본장, 복수 화료자 정산도 동일하게 처리한다. 순위 변동 애니메이션을 만들기 위해 실제 점수 데이터를 프레임마다 바꾸지 않는다. 모바일에서는 항상 필요한 점수·리치·친 정보는 남기고 상세 순위는 펼쳐 볼 수 있게 한다.

여성 캐릭터 중심이라는 방향에 맞춰 이번 버전은 성인 여성 4명으로 구성한다. 아래 이름·외형·테마는 제작 기본안이다. 기존 캐릭터의 흔적을 복제하지 말고 한 작품처럼 선·채색·얼굴 비율·광원·의상 밀도를 통일한다. 3D 모델이나 Live2D를 필수로 요구하지 않으며, 완성도 있는 2D 자산과 코드 애니메이션으로 구현한다.

먼저 기준 캐릭터 이미지를 만들고 후속 표정·컷인은 실제 기준 이미지를 참조하여 제작한다. 표정마다 다른 사람처럼 보이거나 손·소품·의상이 갑자기 바뀌지 않도록 검수한다. 대국 중에는 작은 초상화와 짧은 반응으로 존재감을 주고, 전신 일러스트가 상시 패를 덮지 않게 한다.

상황별 대사는 대국 시작, 울기, 리치, 화료, 만관 이상, 실점, 유국, 순위 상승·하락, 대국 종료에 연결한다. 중요한 상황은 캐릭터별로 복수의 문장을 준비하고 반복 방지·빈도 설정·끄기를 제공한다. 같은 상황에도 공격형·수비형·균형형의 어조가 다르게 느껴지게 한다. 대사와 표정으로 숨겨진 패나 위험패의 정답을 유출하지 않는다.

## 11. 소재와 음향 직접 제작

사용자가 준비한 캐릭터 이미지·표정·컷인·음성·효과음은 없다. 제작자는 사용 가능한 이미지 생성·편집·음향 도구를 확인하고 캐릭터, 패 디자인, 배경, UI 아이콘, 이펙트, 짧은 대사와 효과음을 직접 제작·통합한다. 작업을 사용자에게 넘기거나 ‘나중에 이미지 삽입’ 상태로 완성이라고 보고하지 않는다.

캐릭터 이미지 대신 이모지·글자 아바타·단순 실루엣을 최종 결과로 제출하지 않는다. 외부 게임 이미지 핫링크나 출처를 확인하지 않은 음성·음악을 사용하지 않는다. 제작·사용 출처, AI 생성 여부, 사용 조건과 실제 파일 위치를 자산 목록에 기록한다.

캐릭터 반응은 한국어 자막을 기본으로 한다. 짧은 선언·상황 대사를 위한 음성 파일과 패 선택·버리기·공탁봉·화료 효과음을 제작할 수 있는 도구가 있으면 실제 자산으로 연결한다. 유료 서비스·타인의 목소리·외부 계정 권한은 임의로 사용하지 않는다. 실제 음성 제작 수단이 없으면 텍스트와 효과음으로 정상 플레이되는 상태를 제공하고, 미제작 음성 목록과 교체 인터페이스를 따로 명시한다. 무음 파일이나 호출하지 않는 코드를 넣고 음성을 제작했다고 주장하지 않는다.

음향은 사용자 시작 입력 이후에 활성화하고, 재생이 거부되어도 게임은 정상 작동하게 한다. 효과음·음성은 독립적으로 볼륨 조절·음소거가 가능해야 한다. 대사는 연속으로 겹치지 않게 우선순위와 대기열을 관리한다. 기존에 없는 배경음악 제작을 핵심 기능보다 우선하지 않는다.

자산은 캐릭터 ID·표정 ID·컷인 ID·음향 ID로 참조하고, 파일 교체 시 게임 규칙 코드를 수정하지 않도록 매니페스트로 관리한다. 필요한 이미지를 압축·지연 로딩하되 실제로 필요한 컷인이 로딩되지 않아 중요한 연출이 빈 화면이 되지 않게 한다. 로딩 실패 시 읽을 수 있는 텍스트·정적인 결과 화면으로 복구하고 누락을 기록한다.

## 12. 실제로 다른 CPU 성향

CPU 성향은 대사나 아이콘만 다르게 만드는 것이 아니다. 기존 난이도와 별도로 성향을 분리하여 공격형·수비형·균형형이 실제 선택에 영향을 받게 한다.

공격형은 손의 속도와 기대 타점을 위한 울기·리치·승부 비중을 높이고, 수비형은 공개된 위협에 대한 위험 관리와 안전한 선택 비중을 높인다. 균형형은 손패 진행도·점수 상황·남은 국면을 종합하여 조절한다. 성향 때문에 무조건 위험패를 버리거나 무조건 내려앉는 식의 단순 분기는 피한다.

형태 효율·유효패·타점 기대·울기·리치·위험 관리의 가중치를 설정 데이터로 분리하고 판단 로그를 검수용으로 남긴다. CPU는 자신의 손패와 합법적으로 공개된 정보만 사용한다. 상대의 숨겨진 손패, 패산 순서, 미공개 도라를 읽지 않는다. 각 성향에 다른 패산을 주거나 승패를 미리 조정하지 않는다.

게임과 CPU 선택용 난수는 재현 가능하게 관리하고, 말풍선·표정·입자 같은 장식용 난수와 분리한다. 동일한 국면 묶음과 여러 시드에서 행동 경향을 비교해 차이를 검증한다. 한 번의 대국 결과만으로 성향이 구현됐다고 결론 내리지 않는다. AI 계산이 입력·애니메이션을 막는지 측정하고 필요한 경우 작업을 분리한다.

## 13. 개입 강도를 고르는 초보자 가이드

가이드는 ‘끄기 / 요청할 때만 / 상황별 자동 안내 / 멈춰서 알려주는 튜토리얼’의 네 수준으로 구현한다. 기본안은 상황별 자동 안내이며 처음 설정에서 쉽게 바꿀 수 있게 한다. 패 보조 표기, 실제 도라 안내, 추천 버림패, 같은 종류의 공개패 강조, 캐릭터 대사, 연출은 가이드 수준과 독립적으로 조절한다.

가이드 끄기는 학습 설명을 끄는 것이다. 불가능한 행동 안내, 필수 상태 표시, 오류 메시지까지 없애지 않는다. 자동 안내는 대국의 핵심 영역을 가리지 않으며, 일시정지형 튜토리얼은 어느 시점에서 멈췄는지 분명히 하고 정확한 상태에서 재개한다. 이미 본 설명은 필요 이상 반복하지 않게 하되 도움말에서 다시 확인할 수 있도록 한다.

패 종류·기본 완성 형태·내 차례와 쯔모패·울기·멘젠·역과 도라의 차이·리치와 공탁금·텐파이와 대기패·론과 쯔모·후리텐·유국·본장·점수와 등급 등을 실제 대국 상황에 맞춰 설명한다. ‘역이 없다’, ‘후리텐이다’, ‘이 패는 리치 선언패로 선택할 수 없다’ 같은 안내는 엔진의 실제 판정 이유를 사용하고 일반 문구로 둘러대지 않는다.

추천에는 선택 이유를 짧게 설명하되 정답·승리 보장처럼 표현하지 않는다. 남은 패 수 안내는 공개 정보에서 계산한 범위와 실제 패산 정보를 구분하며 숨겨진 실제 남은 수를 읽어 보여주지 않는다. 모바일 설명 패널을 여닫는 입력이 뒤의 손패에 전달되지 않게 한다. 초보자 학습을 위해 불필요한 제한시간이나 강제 자동 버리기를 추가하지 않는다.

## 14. 현재 구조 정리와 향후 기능 설계

현재 규칙 코어, CPU 정책, 플레이어별 관측 데이터, 입력 컨트롤러, 화면 렌더러, 연출·음향, 가이드, 저장, 자산 데이터를 분리한다. 기존 JavaScript를 유지하거나 필요한 부분을 타입화할 수 있지만, 유행하는 프레임워크로 바꾸기 위한 전면 재작성은 피한다. 기존 테스트를 계속 실행할 수 있는 단순하고 유지 가능한 구성을 선택한다.

실제 상태를 변경하는 규칙·정산과 보여주는 값만 바꾸는 애니메이션은 분리한다. 이벤트에는 순서 번호와 중복 처리 방지 수단을 두고, 중단·재개·저장 복원 때 이미 처리한 행동을 다시 적용하지 않는다. 화면에 전달되는 데이터는 해당 플레이어가 볼 수 있는 정보로 제한한다.

### 향후 설계 산출물

**대전 모드 분리:** 공통 대국 화면에 CPU 로컬 대전, 향후 일반전, 향후 랭크전이 서로 다른 세션 어댑터로 연결되는 구조를 설계한다. 현재 구현 어댑터는 CPU 대전 하나다. 향후 실시간 대전에서는 서버가 권위 있는 판정을 담당하고, 클라이언트가 상대 비공개 정보를 받지 않는 경계를 명시한다. 매칭·인증·랭크 산식·운영 서버는 이번에 구현하지 않는다.

**패보:** 경기 식별자, 규칙·엔진·스키마 버전, 초기 좌석·캐릭터·성향, 라운드 정보, 초기 재현 정보, 순서가 있는 행동·결과 이벤트, 점수·공탁 변동, 결과를 담는 데이터 형식을 문서와 타입·예시 JSON으로 설계한다. 패 종류와 실물 패 ID, 공개 정보와 비공개 정보를 구분한다. 진행 중 공유 가능 데이터와 종료 후 복기 데이터의 공개 정책을 분리한다. 시드만 저장하면 충분하다고 단정하지 말고 난수·엔진 버전과 실제 결과 이벤트의 재현 전략을 포함한다.

**리플레이:** 패보를 소비하는 별도 읽기 전용 세션으로 설계한다. 재생·정지·한 수 전후·배속·국 이동·플레이어 시점·종료 후 전체 공개를 계획하고, 특정 지점 탐색을 위한 스냅샷·이벤트 재적용 전략을 정한다. 되감기 때 실제 대국 점수를 되돌리거나 AI를 새로 실행하여 다른 판단이 나오게 하지 않는다. 이번에는 실제 리플레이 재생 UI를 구현하지 않는다.

**전적 통계:** 총 대국 수·평균 순위·순위 분포·화료율·방총률·리치율·후로율·평균 화료 점수 등의 후보 지표를 정의한다. 각 지표의 분모·분자·집계 단위와 유국·중도 종료·복수 론 처리를 명시한다. CPU전과 향후 대인전을 구분하고 서로 다른 규칙·버전 데이터를 무심코 섞지 않도록 설계한다. 테스트·연출 미리보기는 통계 대상에서 제외한다. 현재 통계 대시보드나 계정 기반 누적 저장을 구현하지 않는다.

이 네 기능은 문서·타입·인터페이스·샘플 데이터·검증 계획으로 남긴다. 작동하는 실제 기능으로 보고하지 않는다.

## 15. 웹 배포·저장·실행 안정성

단일 HTML 파일에 모든 자산을 다시 넣는 것을 목표로 하지 않는다. HTML·CSS·JavaScript·이미지·음향을 관리 가능한 구조로 분리하고, 정적 웹 호스팅에 올릴 수 있는 배포 결과물을 만든다. CPU 대전의 실제 플레이에 별도 계정이나 유료 API 서버를 필수로 요구하지 않는다.

배포 대상이 이미 연결되어 있고 권한이 있으면 해당 환경의 기존 배포 절차를 확인하여 실행한다. 배포 대상이나 권한이 없으면 배포 가능한 빌드와 필요한 설정·절차를 제공하고, 접속되지 않는 주소를 만들어 배포 완료라고 하지 않는다. 권한 없이 서비스를 생성하거나 비용을 발생시키지 않는다.

현재 진행 저장과 사용자 설정은 버전이 있는 형태로 관리한다. 기존 저장 데이터는 안전한 검증·변환 가능 여부를 확인하고 불가능하면 원본을 보존한 채 명확히 안내한다. 기존 로컬 파일의 저장 상태가 새 웹주소로 자동 이동한다고 약속하지 않는다. 개인 브라우저 저장을 계정 동기화라고 부르지 않는다.

에셋 누락·음향 재생 거부·저장 차단·연출 중 이탈·백그라운드 복귀·회전·리사이즈·낮은 화면 높이를 처리한다. 설정은 재접속 후 유지되어야 하며 저장을 사용할 수 없을 때도 현재 대국은 진행할 수 있게 한다. 저사양 모드에서는 입자·블러·흔들림부터 줄이고 패 선명도·현재 상태 표시는 유지한다.

## 16. 진행 순서와 검수 기준

진행 순서는 기존 코드·테스트 확인 → 상태·입력·화면 경계 정리 → 패·버림패·리치·모바일 레이아웃 → 캐릭터 기준 자산·표정·컷인 제작 → 실제 화료·점수·순위 이벤트 연동 → CPU 성향·가이드 → 통합 검수·웹 배포 결과물 정리로 잡는다. 이는 의존성에 따른 순서이며 기능의 중요도를 낮추는 근거가 아니다.

다음 항목은 실제로 검수하고 결과를 기록한다.

| 구분 | 필수 검수 |
|---|---|
| 선택·확정 | 미선택 패 첫 입력은 선택만, 같은 실물 패 재입력은 버리기, 다른 패는 선택 변경, 느린 재입력도 정상 동작. |
| 드래그 | 유효 영역 드롭만 확정, 영역 밖·작은 이동·취소·회전·차례 변경은 취소, 드래그 후 클릭으로 중복 버림 없음. |
| 원클릭 금지 | 모든 설정·모드·입력 경로에서 미선택 상태의 한 번 클릭 즉시 버리기가 없음. |
| 리치 | 네 좌석의 선언패가 실제 가로 방향, 인접 패와 겹침 없음, 성립 전후 표시 구분, 공탁봉·점수·배지 일치, 선언패 론 등 예외 검증. |
| 왕패·도라 | PC·모바일 좌측 상단에서 판독 가능, 표시패와 도라 구분, 깡도라 공개 시점 일치, 미공개 정보·우라도라 누출 없음. |
| 화료 | 일반·만관·하네만·배만·삼배만·역만, 친·자·론·쯔모·복수 화료의 실제 결과와 연출 일치. 지원하지 않는 결과를 가짜로 만들지 않음. |
| 건너뛰기 | 어느 단계에서 생략해도 점수·공탁·순위가 정확히 한 번 정산되고, 입력 잠금 해제·다음 국 이동이 정상. |
| 순위 | 실제 전후 점수에 따른 순위 변화, 동점 규칙 유지, 카운트업 중 허위 순위 변동 없음. |
| 캐릭터·음향 | 실제 자산 로딩, 표정·컷인 일관성, 사건에 맞는 대사, 겹침·과도한 반복 없음, 음소거·재생 실패 시 정상 진행. |
| CPU | 동일 정보 조건에서 성향별 판단 차이, 비공개 정보 미참조, 게임 난수와 장식 난수 분리. |
| 가이드 | 네 수준별 개입 차이, 단계별 정확한 일시정지·재개, 패 보조 표기와 독립 설정, 엔진 상태에 맞는 설명. |
| 화면 | 대표 PC·모바일 가로 크기에서 손패·버림패·행동 버튼 겹침·잘림 검수, 모바일 확대·회전·안전 영역 처리. |
| 회귀 | 기존 규칙·점수·CPU 대국 테스트 재실행, 수정한 룰의 재현 테스트 추가, 실제 대국을 끝까지 진행. |
| 설계 전용 | 모드 분리·패보·리플레이·통계 산출물이 문서·타입·예시로 구분되고 미구현 기능을 완료로 표시하지 않음. |

가능한 환경에서 Chromium과 WebKit 계열을 확인한다. 에뮬레이션과 실제 기기 테스트를 구분하고, 수행하지 못한 환경을 통과했다고 쓰지 않는다. 기존 테스트 기록뿐 아니라 이번 실행 명령·결과·대표 캡처·재현 방법을 남긴다. 스크린샷만 있는 연출 샘플과 실제 대국 이벤트 연동 테스트를 구분한다.

## 17. 최종 산출물과 보고 형식

실행 가능한 웹게임 소스와 배포 빌드, 캐릭터·패·이펙트·음향의 실제 제작 파일 및 자산 매니페스트, 실행·배포·조작·설정 설명서, 기존 버전 대비 변경 내역, 현재 하우스 룰과 제한사항, 향후 대전 분리·리플레이·패보·전적 통계 설계 문서와 타입·예시 데이터, 테스트 결과 및 PC·모바일 캡처를 제출한다.

캐릭터별 이름·역할·외형·표정·컷인·상황 대사·CPU 성향 설정은 별도 데이터로 제공한다. 빠르게 연출을 검수하는 개발용 미리보기는 실제 대국 상태와 분리하고 제품의 일반 대국에 치트 기능처럼 섞지 않는다.

마지막 보고에서는 ‘이번에 실제 구현·검증한 것’, ‘구현했지만 검증하지 못한 환경’, ‘설계만 한 것’, ‘미제작·미완료인 것’을 구분한다. 제작하지 않은 음성, 존재하지 않는 배포 주소, 재실행하지 않은 테스트를 완료로 표시하지 않는다. 범위가 큰 경우 작동하는 중간 결과를 보존하고 정확히 남은 작업을 기록하되, 요구사항을 임의로 삭제한 결과를 완성본이라고 부르지 않는다.

최종 목표는 화려한 그림이 붙은 기존 HTML이 아니다. 패가 또렷하게 읽히고, 선언·공탁·점수 변화가 자연스럽게 전달되며, 성향이 다른 캐릭터와 대국하는 재미가 있고, 초보자도 설명의 개입을 조절하면서 배울 수 있는 월영마작이다.
